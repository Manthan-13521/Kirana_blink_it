## Production rollover checklist

1. Obtain approval for the retention cutoff and maintenance window. Confirm headroom for both databases and import writes. Record the current Worker version, database binding and provider webhook configuration. Keep independently verified encrypted copies and a Time Travel bookmark before changing any binding.
2. Before closing writes, validate an isolated import with representative order counts, line totals, stock balances, unresolved orders, active refund and payment state, original invoice data and authorization on historical lookups. Preserve request keys and provider event and payment identifiers wherever retry can still reach the active application. Leave unresolved and unreconciled records in the active database. The owner-only offline encrypted invoice retrieval has been rehearsed. A release still requires authenticated in-application history and cross-boundary replay coverage.
3. For a separately approved cutover, close customer checkout and stop counter, owner, rider and Cron mutations for the final snapshot. Preserve provider delivery and retry continuity. Any callback path placed in maintenance must fail retriably until the new database is authoritative. Drain in-flight operations, take the final encrypted snapshot, reconcile deltas and document the exact point at which the source stops receiving writes.
4. Switch the existing Worker binding only after all validation passes. With writes still paused, verify owner-only historical retrieval, open order continuity, payment reconciliation and checkout replay behavior. If a check fails before new writes, restore the original binding and verify it before reopening. If any write lands on the candidate, hold writes and reconcile those changes before switching back. Keep the old database and recovery evidence until the approved retention procedure takes effect.
